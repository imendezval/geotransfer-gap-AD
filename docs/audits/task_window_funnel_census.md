# Task and window candidate funnel census

The reproducible census is generated by [report_task_window_funnel.py](../../src/geotransfer_gap/corpus/report_task_window_funnel.py). It reads retained source selectors, historical gate ledgers, the current selection snapshot, and the frozen manifest. Detailed JSON and CSV files are written under `artifacts/audits/task_window_funnel/`.

Run it from the repository root with:

```sh
PYTHONPATH=src python -m geotransfer_gap.corpus.report_task_window_funnel
```

The generated `census.json` records the exact input path and SHA256 for all 129 input records. It includes 34 parsed source selectors, 21 historical candidate gate ledgers, 28 raw scan or map-preflight inventories, two older scene-window ledgers, and saved scene-gate files. The raw scans are reported per file and do not enter the task/window funnel. The parsed selector list includes `body_task_selection`, `footprint_task_selection`, `fine_phase_task_selection`, `slow_approach_task_selection`, `step2_source_task_selection`, and the source restart and following queues.

## Identity and stage rules

Actor-paired windows use `(recording, ego, first_frame, actor)`. Tasks use `(recording, ego, actor)`. Repeated selector snapshots are deduplicated only on the full window key. Actorless evidence remains scene-window evidence.

The candidate-window and task tables keep gate stages as nonexclusive flags. `unresolved_semantics_screen` records a hard semantic exclusion under its producer. `awaiting_manual_review`, source failures, technical failures, technical admission, unattempted windows, and deferred windows remain separately visible. Historical gate rows are counted with their producer fingerprint group. Six rows with no fingerprints remain under unknown provenance.

Planner admission and technical admission from saved scene gates are stored in `current_scene_decisions.csv`. The frozen manifest names 13 interaction actor IDs. The census marks independent selection only when recording, ego, first frame, and actor all match a manifest row. Those manifest memberships are claims recorded by the manifest. They do not transfer a technical or planner gate result to other actors or phases.

## Historical attempts and backlog

The 21 historical candidate gate ledgers contain 814 retained attempt rows. They include 808 actor-paired rows and six scene-window rows. The paired rows record 43 technical admissions across 42 exact windows. Those 43 rows are also marked `awaiting_manual_review`. The status counts include 599 hard semantic exclusions, 80 source failures, and 86 technical failures. Six actorless velocity-repair rows have unspecified statuses and unknown producer fingerprints.

The attempt table keeps each recorded reason with its original field name. The producer-version summaries count reasons under their exact status and version. This includes source-unsupported rules, unresolved rule flags after source proofs, technical-gate reasons, and exclusion reasons. An empty reason field stays empty when a ledger records a status without details.

The source selectors and exact gate identities leave a bounded set of 5,197 task-evidence-qualified windows with no exact retained gate record. The historical flow index declared 54 deferred actor-pair windows. Twenty-one later received an exact attempt and 33 remain deferred and unattempted. At the task level, 373 of the 591 source-positive tasks have at least one exact attempt, while 459 have at least one unattempted source-positive window. Task-stage totals overlap because a task can have several windows at different stages.

The backlog is an observed count of source-positive candidates. It can contain scene or actor overlaps, stale contracts, and candidates that fail later gates. It does not estimate usable tasks or admissions. No pooled admission rate is reported.

Two older scene-window ledgers each contain 1,030 rows. Their actor identities are not preserved as task pairs and their per-row producer fingerprints are absent. The older IDM ledger records 293 ever-run full gates. The hybrid-startup ledger records eight. Both record zero current full gates and zero technical admissions. These rows stay separate from actor-pair counts.

## Saved selection evidence

The saved scene-selection files record 20 review candidates, 18 technical admissions, 17 planner/research admissions, and 16 independently selected scenes. The frozen manifest identifies 13 interaction actor pairs. These values are reported as saved. The census does not recompute frozen gates after later source changes. An independent review after viewer changes found a `tool_artifacts.py` SHA mismatch in seven saved hybrid technical contracts, so their historical `technical_gate_current` fields are not presented as live checks.

## Generated files

- `census.json` contains the input manifest, status and reason counts by ledger and producer version, selector breakdowns, and schema limits.
- `candidate_windows.csv` gives one row per unique actor-pair window with source origins, exact gate history, and exact manifest membership.
- `tasks.csv` gives one row per recording + ego + actor task, with window counts and nonexclusive stage flags.
- `third_family_windows.csv` and `third_family_tasks.csv` isolate the 4,982 / 394 cohort.
- `attempts.csv` preserves each retained gate row and its source file, status, fingerprints, and identity scope.
- `producer_versions.csv` keeps compact status and reason totals by version. Its reason-detail reference points to the complete per-version counts in `census.json`. Full per-attempt reasons remain in `attempts.csv`.
- `manifest_actor_pair_memberships.csv` expands the frozen manifest's explicit actor IDs into exact window keys.
- `current_scene_decisions.csv` and `legacy_scene_ledgers.csv` preserve scene-level decisions and older scene-only rows.
