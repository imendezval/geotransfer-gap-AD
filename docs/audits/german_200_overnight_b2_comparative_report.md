# German-200 B2 Expert-traffic diagnostic comparison

**Status:** B2b native campaign and B3 offline evaluation accepted as diagnostic evidence. Research admission, safe-completion criteria, and population performance are not established. This report summarizes 16 fixed scenes across Expert, IDM, PPO, and SMART ego controllers under Expert replay traffic.

## Scope and protocol

The matrix contains 64 accepted cells in manifest order under manifest SHA-256 `316438458c537adfd6b3347a8387844c95ac806d2067365fdc0d72abe2b3992c`. Every run requested 91 observation frames, immediate Expert traffic, ten replay warmup transitions, CPU execution, and a schema-v2 evaluation capture bound to the trace. B3 used the existing offline evaluator with the default profile and isolated Shapely; no native or model run was performed during B3. The command records and wall times are in [the B3 command log](../../runs/german_200_overnight/planner_diagnostics/evaluations_b3/commands.txt), and full evaluator receipts/logs are linked below.

The evaluator records planner goal visibility as `true` for PPO, `false` for SMART, and `not_applicable` for Expert and IDM. Static interface inspection supports the direct-input distinction between PPO and SMART; `not_applicable` does not characterize the native IDM route representation. The common source task is goal-bound in the evaluator, but the controllers do not share matched navigation-goal inputs. All traffic after warmup is replayed Expert traffic and does not respond to the tested ego trajectory. The interaction outcomes therefore describe sampled geometry and handling in the replayed scene, not the response of reactive traffic or a yielding/compliance result.

## Comparative matrix

Each controller cell reports the bound native goal-counter event separately from the last observed pose. ADE is exact-timestamp source deviation in metres, with matched samples over the fixed 76-sample primary support. FDE reasons are abbreviated as **H** (requested horizon not reached) or **B** (fixed primary endpoint outside source task bounds). The supplemental last-pose distance is a straight-line distance to the fixed source goal. Its step, recorded time, pose coverage, and 91-frame request are preserved in the [supplemental distance receipt](../../runs/german_200_overnight/planner_diagnostics/evaluations_b3/last_pose_goal_distance_b4.json), SHA-256 `345d77befd3bbaa2723f913f474583575f0aba55b785a404410bd53756000b76`. For each frame I selected the unique `state.actors` row matching the pinned ego source ID and binary index, then computed `sqrt((x−goal_x)²+(y−goal_y)²)` from the last present finite pose. Coverage is valid present ego poses divided by recorded trace observations. It is not FDE, route progress, or the evaluator's completion decision.

The route field shows signed progress and normalized progress only when a hash-bound source route certificate and continuous projection are both available. `C/O` are primary-window native collision/offroad onsets. Mapped-surface outside counts are separate. Observed distance and stationary duration are also primary-window metrics. Clearance is the minimum sampled oriented-footprint gap over eligible pairs; TTC is a fixed-heading, constant-velocity projection within the evaluator's five-second horizon. Near-miss flags show whether the threshold-duration window coverage is complete, partial, or unavailable. Family values are source opportunity plus evaluator realization/outcome and supported measurements; they are not a rule pass.

## Recurrent candidate patterns and limits

1. Completion differs across the fixed diagnostic matrix: 16/16 Expert, 8/16 IDM, 13/16 PPO, and 5/16 SMART matched a positive bound goal counter. SMART also has the largest number of unresolved rows (11/16); this is an observed pattern, not an explanation.
2. Native collision/offroad channels occur only on zero-counter rows; those 11 rows end with `ego_removed`. The saved evidence does not establish removal cause. The remaining zero-counter rows are horizon-censored, not goal failures.
3. All last present poses are outside the completion radius, including goal-counter-completed removal cells. The task result follows the captured native goal event when source-goal binding matches; the pose-less terminal snapshot prevents exact event-pose distance measurement.
4. The evaluator reports navigation-goal visibility `true` for PPO in all 16 cells, `false` for SMART in all 16, and `not_applicable` for Expert and IDM. This captures the inspected PPO/SMART direct-input difference; it does not describe IDM’s internal route representation. Outcome differences cannot be attributed to goal visibility from this matrix.
5. Route progress is defensible only in four cells. In the two certificate scenes, supported normalized progress is approximately 85.5% for Expert+SMART in `r01_e280_f18833`, and 79.1% for Expert+IDM in `r07_e200_f25439`. This does not support route-based comparison for the other 60 cells.
6. Expert traffic follows saved replay paths instead of reacting to the tested controllers. B2b compared 13,203 post-warmup traffic positions to the source with zero errors above 1 mm and zero traffic ownership violations; that verifies replay fidelity, not interactive response. Scene rows also cluster into 10 recordings across 3 locations, so they are not 16 independent recording units and do not establish geographic transfer.

The runs are `diagnostic_only`, with controller-pair research admission not established, original source admission not recorded, and task preservation not assessed. The fixed Expert traffic, PPO/SMART direct-input difference, limited route certificates, incomplete map semantics, and clustered scenes bound all comparisons. Do not interpret the table as an admitted controller ranking or as yielding/rule correctness.
