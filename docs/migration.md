# Repository transformation

The project directory is now `geotransfer-gap-AD`, matching the existing remote
`https://github.com/imendezval/geotransfer-gap-AD.git`. The Python package is
`geotransfer_gap`; the command is `geotransfer`. Historical directory aliases and
old executable entrypoints are removed at cutover.

## Preservation and compatibility

The first development commit preserves the original 92 scripts and research
notes. `archive/legacy-v1.tar.gz` is a local, ignored recovery snapshot of 33,764
original files. `archive/legacy-v1.sha256.json` records every regular file's hash;
archive contents were verified before migration. `archive/environment.txt` records
the original BB Python environment. Datasets, BB and weights remain external.

Do not restore the archive over the current checkout. Extract into a separate
scratch directory and verify against the checksum index. Old evidence records
original absolute paths and source hashes; its original layout must be restored
for literal historical execution. The migration checker restores verified source
into `/tmp` and links the configured external dependencies itself.

The inventory `configs/tool_inventory.json` accounts for all 92 old entrypoints.
Each has a current package/test destination or an explicit archive disposition.
`docs/commands.md` gives replacement commands. Rejected source-speed/reference-route
variants are recoverable history, not production switches. Their useful cases are
retained in the current source/traffic/admission regression suites.

## Equivalence standards and evidence

The cutover requires:

- All 16 retained scenes regenerate byte-identical JSON, binaries and BB manifests.
- Old and new SMART inference tensors, actions and meaningful evaluator-state
  traces match exactly for all 16; the native runtime hash remains
  `beedf8f1b0e9c490`.
- Fresh technical and SMART admission preserves the same reviewed tasks. Source
  interaction labels and exclusion standards do not change.
- All 16 single-scene timelines match fresh isolated batch runs.
- Native map/lateral checks, US interfaces, lifecycle/re-entry, source scope,
  traffic/map preprocessing, queue resume and admission regressions pass.
- Ordinary run/view commands leave reviewed inputs unchanged; the offline viewer
  works without a server and aligns source/converted/expert/SMART states.

`artifacts/audits/migration_conversion_equivalence.json` and
`migration_execution_equivalence.json` hold the conversion and old/new execution
results. Per-scene captures and review equivalence certificates are retained under
`artifacts/migration/` and each scene's `testing/` directory. Final verification
is summarized in `artifacts/audits/migration_acceptance.json`.

Native storage for unborn actors and background goal flags is not a defined
observation. The trace recorder emits null absent-state numeric fields and only
reports the ego's goal flag. This normalization does not alter simulation or
planner inputs and is applied equally to old/new reference captures.

Existing reviews are not regenerated by a model or silently marked complete.
Carry-forward compares the originally reviewed source, binary, image, physical/
map/rule/interaction evidence and any reviewed certificates. Only producer/hash
bindings can change. Each carried review records the exact original document and
checks. A substantive difference fails migration and needs renewed review.

## Re-run verification

```bash
.venv/bin/pytest -q
.venv/bin/geotransfer check all
.venv/bin/geotransfer check migration conversion
.venv/bin/geotransfer check migration execution
```

The execution comparison restores exact original source from the local verified
archive into `/tmp`; it does not require old scripts at the project root. Native
map checks require the optional `lanelet2==1.2.3` extra. The BB checkout is kept
unchanged. The root README and workflow guide describe supported commands; older
research reports retain historical commands as evidence rather than instructions.
