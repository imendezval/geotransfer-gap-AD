# Shared scene and controller evidence plan

## Goal

Build an additive admission chain for controller comparisons. Reuse source and task evidence across controllers when its inputs are identical, and require fresh evidence for each controller input path and traffic protocol. Keep the fixed source-only selection and the original SMART/hybrid admissions unchanged. Matrix execution and exact single/batch parity remain integration checks. They do not establish research admission.

The chain must report four independent dimensions.

| Dimension | What it establishes | What it does not establish |
| --- | --- | --- |
| Observation validity | The controller received the declared, current inputs for its role and produced valid outputs under the pinned model protocol | Traffic realism or useful driving |
| Traffic fidelity | The declared traffic producer, source prior, startup policy and native runtime behaved under their recorded protocol | Scene task eligibility or planner quality |
| Task and semantic eligibility | Source-selected scene contains the reviewed task and applicable rules are represented or shown irrelevant for the controller being evaluated | That a planner succeeds |
| Planner performance | Outcome measures from the prespecified run set | Permission to select scenes, alter admission, or exclude a poor result |

## Current behavior and gaps

- [`admit_scene.py`](../../../src/geotransfer_gap/validation/admit_scene.py) refreshes technical reports, builds the scene contract and writes `testing/admission.json` or `testing/admission_hybrid_startup.json`. `technical_admitted` excludes its research-only checks. Technical checks still include source/binary reconstruction, evaluator configuration, source lifecycle and interaction-related execution evidence for the selected traffic protocol. `research_admitted` additionally needs current rule, semantic review, source-supported irrelevance and interaction evidence. Hybrid startup adds its own lifecycle and counterfactual checks. US-mechanics parity remains a research-admission gate and does not contribute to `technical_admitted`.
- [`admit_smart_scene.py`](../../../src/geotransfer_gap/validation/admit_smart_scene.py) reads that protocol-specific base gate and adds SMART-specific German and US input probes, model/codebook/adapter fingerprints, actual map-token checks, source feature fidelity, interaction review, task-rule scope and essential leading context. Its output is `testing/admission_smart_<protocol>.json`. It has no corresponding PPO or IDM admission producer.
- [`planners/protocol.py`](../../../src/geotransfer_gap/planners/protocol.py) fingerprints SMART producers and execution files. The SMART proof checks the actual adapted map and causal observed history. [`faithful_smart.py`](../../../src/geotransfer_gap/planners/faithful_smart.py) rejects source-future prediction loading. The observed-birth velocity bootstrap is an explicit input and must remain disclosed.
- [`ppo_policy.py`](../../../src/geotransfer_gap/planners/ppo_policy.py) pins the BehaviorBench revision, checkpoint and evaluator INI, validates the 1151-wide observation and action contract, and strictly loads model state. Runtime provenance describes PPO's native agent-centric view, which includes a simulator navigation goal derived from the final valid source position. The PPO adapter has unit and upstream-parity coverage, but no scene-specific PPO observation or task-semantic admission.
- [`idm_controller.py`](../../../src/geotransfer_gap/planners/idm_controller.py) returns native IDM intents. [`scheduler.py`](../../../src/geotransfer_gap/runtime/scheduler.py) owns native writes and enforces one episode-global IDM parameter set. [`background_route_intent.py`](../../../src/geotransfer_gap/runtime/background_route_intent.py) may supply a source-informed route prior to background IDM vehicles. Ego IDM uses native lane routing. These producers and their outputs need separate fidelity evidence. IDM has no learned observation proof because it is a native controller.
- [`run_trace.py`](../../../src/geotransfer_gap/runtime/run_trace.py), [`execution.py`](../../../src/geotransfer_gap/execution.py) and [`matrix_campaign.py`](../../../src/geotransfer_gap/matrix_campaign.py) preserve the original source admission only when its official manifest and pinned file hashes match. New matrix evidence is explicitly `diagnostic_only`, `controller_pair_research_admission: not_established` and `task_preservation: not_assessed`. Exact trace parity validates reproducibility, not admission.
- [`verification_matrix.py`](../../../src/geotransfer_gap/verification_matrix.py) requires the current 16-scene manifest, each frozen `admission_smart_hybrid_startup.json` hash, and matching source/binary inputs. The old SMART/hybrid artifact is therefore part of a frozen identity. Re-running the current SMART gate can overwrite that path and invalidate the manifest.

## Target evidence layout

Add new versioned evidence paths. Do not change the schemas or contents of the existing admission files as part of migration.

1. `testing/scene_admission_shared_v1.json` records source identity, technical reconstruction, task eligibility and semantic review. It references exact producer and input fingerprints. Keep source-only selection identity and its reviewed manifest outside planner outcomes. A technical pass and a task-eligible pass are separate fields.
2. `testing/controller_input_<controller>_<role>_v1.json` records controller-specific observation or native-control validity. Bind it to the shared scene record, model/runtime identity, effective observation/action protocol and role. SMART and PPO require actual-input evidence. IDM records native inputs, mode readback and parameters. Its observation status is `not_applicable_native`.
3. `testing/traffic_protocol_<controller>_<startup>_v1.json` records traffic fidelity independently from model input. Identify the traffic actor set, native runtime, controller parameters, route or release producer, source prior, and observed lifecycle/physics evidence. `source_hold` release timing and IDM background route intent are source-informed producer inputs. They must be labeled as schedule/route priors, not learned model observations.
4. `testing/controller_pair_<ego>_<traffic>_<startup>_v1.json` is a derived reference record. It may report research eligibility only when the shared scene/task record, both role-input records, applicable traffic-protocol record, and task-relevant semantic visibility evidence are current. Keep run outcomes in the existing verification/evaluation outputs. Pair records must not read success, collision, goal completion, progress or aggregate score to decide scene selection or admission.

Each record carries schema and protocol versions, source references and SHA-256 values, producer fingerprints, status per gate, failure reasons, and parent-record hashes. Missing evidence is `not_established` or `blocked`. It must never default to pass. The derived pair record stores gate status and evidence links. Mutable claims from a run are excluded.

### Controller-specific evidence

- **SMART** — Prove the live map, road tokens, scene frame, observed actor features and prediction targets match the declared scene and role. Preserve the actual-planner token proof, finite inference, warmup/history settings, refresh identity, source-feature comparison, and future-mutation invariance. Bind each role to the SMART adapter, map encoder, upstream tokenizer/planner, codebooks, weights, runtime, evaluator configuration and traffic protocol. Reuse the existing SMART checks as evidence only when their hashes and protocol match.
- **PPO** — Add scene-and-role input evidence for the exact native `float32[1151]` rows, feature layout and goal information used at inference. Bind it to the pinned checkpoint, BehaviorBench commit, INI, action grid/decoder and runtime. Record the decoder semantics. Deterministic `argmax` selects one of 91 joint actions. Integer division by 13 selects one of seven acceleration bins and the remainder selects one of 13 steering bins. Each bin comes from the pinned `PPOConfig` arrays and is normalized by its maximum absolute value. Require strict full-weight loading, upstream sequence parity, deterministic action behavior and actor-lifetime recurrent-state identity under reorder, birth, gap, retirement and reset. Add task-semantic visibility checks for any rule the admitted task requires. A finite PPO action or successful run is not an observation proof.
- **IDM** — Record native route source, actor eligibility, effective IDM mode, target speed and global IDM parameters. Prove ego and traffic configuration compatibility where both use IDM. For background traffic, bind route coverage and producer hash and distinguish source route segments from terminal extrapolation. Test release-to-IDM initialization when source hold is selected. Check that VRUs, marked-expert vehicles and context retain their declared replay ownership. Task-rule coverage remains a separate eligibility check.

## Migration and invalidation

1. Keep `configs/current_manifest.json`, every existing `admission_smart_hybrid_startup.json`, their reviews, and their hashes unchanged. Do not run a refresh command against the frozen roots during migration. Write new artifacts to the versioned paths above. The original admission remains a historical SMART/hybrid claim with its original scope. It cannot satisfy PPO, IDM, a different traffic protocol, or a changed task protocol.
2. First build shared records from read-only current evidence. Reuse a legacy report only when its contract, protocol, producer hashes and source references match. Leave non-separable or unproven fields `not_established`. Never promote a SMART pass wholesale into a shared pass.
3. Preserve the current source-only cohort and its recorded exclusion flow. Any new cohort requires a separate reviewed source-only manifest version before controller execution. Never rank or filter candidate scenes by any controller's outcome.
4. Source tracks, source map, scene JSON/binary, conversion, evaluator configuration, native runtime or scene-contract producer changes invalidate the shared technical record and dependent records. Rule/task evidence changes invalidate task eligibility and every controller's relevant semantic-visibility evidence.
5. SMART adapter, tokenizer, map encoding, codebook, checkpoint, probe, runtime or SMART traffic protocol changes invalidate affected SMART role and traffic records. PPO checkpoint, model loader, observation layout, action mapping, evaluator setup or runtime changes invalidate affected PPO role records. IDM parameters, native mode behavior, background-route producer, route coverage protocol or startup/release producer changes invalidate affected IDM/traffic records.
6. A startup/source-hold change invalidates that traffic-protocol and pair record. It does not rewrite the shared source/task record unless source identity or task evidence also changed. New evidence uses a new version or campaign generation. Old evidence remains readable and labeled with its original protocol.

## Acceptance and negative tests

- Rebuilding the new records leaves the bytes and SHA-256 values of the frozen manifest and SMART/hybrid admissions unchanged. Existing `original_source_admission` continues to report the pinned legacy record, while all new pair claims remain unestablished until their own evidence passes.
- The same current shared source/task record can be referenced by SMART, PPO and IDM evidence without transferring controller-specific passes. A current SMART proof cannot satisfy PPO, and a PPO proof cannot satisfy SMART. IDM records native-control evidence and cannot claim a learned observation proof.
- Current evidence passes only when all referenced hashes, protocol versions, role, startup and source identities match. Missing, malformed, stale or wrong-role evidence fails closed with the specific gate named.
- Changing only a SMART checkpoint invalidates SMART dependents while preserving shared source validity. Changing the source binary invalidates shared and all dependent records. Changing only source-hold release evidence invalidates source-hold traffic and pair records.
- Unsupported applicable rules, stale manual review, unbound source-image registration, task actor loss before its reviewed decision interval, or absent required task context block task eligibility. A rule can be excluded only through the existing source-bound review and scope certificates.
- Outcome files are not inputs to source selection or scene admission. A collision, early terminal, no goal, or low progress remains in the prespecified result set and is reported as an outcome. A good score cannot upgrade stale evidence or create admission.
- Traffic producer tests detect future-source values entering learned inputs, source route gaps bridged as observed data, incorrect source-hold releases, route-prior leakage to ego IDM, and native mode overrides. Preserve and extend the current source-hold, native PPO, SMART input, lifecycle and legacy SMART regression probes.
